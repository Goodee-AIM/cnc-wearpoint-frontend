# 서버 기준 자동 모니터링

백엔드의 `/api/monitoring/state` 응답을 받아 Set 1~8(원본 Set4~11)의 현재 이미지와 센서 위치를 표시합니다.
프런트 접속 시 DB 측정과 이미지 목록을 자동 조회합니다. 공통 재생의
시작·일시정지·초기화는 서버 운영자가 제어하고, 화면 하단의 분석 시작 버튼만 전체 재생 위치를 처음으로 되돌립니다.
서버가 추론 대기 재생(`gated_playback`)을 사용하면 측정마다 AI 추론 결과를 기다려 표시합니다.

## 로컬 확인

1. 백엔드를 `http://127.0.0.1:8001`에서 실행합니다.
   추론 대기 재생을 확인하려면 백엔드에 `MONITORING_INFERENCE_ENABLED=1`, `MONITORING_ALERT_WORKER_ENABLED=0`과 Serving 연결이 필요합니다.
2. 프런트 폴더의 PowerShell에서 실행합니다.

```powershell
$env:VITE_API_BASE_URL = "http://127.0.0.1:8001"
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

다른 Vite 서버가 5173을 사용하고 있으면 그 서버를 먼저 종료합니다.
백엔드의 CORS_ORIGINS에는 `http://127.0.0.1:5173`이 있어야 합니다.
브라우저에서는 `http://127.0.0.1:5173`으로 접속합니다.
운영자 제어 토큰은 프런트 환경변수에 넣지 않습니다.

아직 일정을 준비하지 않은 백엔드는 서버 재생 대기가 표시됩니다. 한 번 준비한 뒤 reset하면 기존 일정으로 새 세션 1회차가 즉시 재생됩니다.
start·pause·reset은 백엔드 운영자 요청 창에서 `X-Monitoring-Control-Token` 헤더로 실행합니다.

운영자 제어 키는 백엔드 .env의 MONITORING_CONTROL_TOKEN에 설정합니다.
실제 키는 문서나 Git에 기록하지 않습니다.

이미 실행 중이면 같은 세션을 반환합니다.

| 테스트 | 통과 기준 |
| --- | --- |
| A 창 접속 | 버튼 조작 없이 현재 이미지, 그래프, 상태 표시 |
| 10초 뒤 B 창 접속 | 같은 Set의 같은 측정 위치를 표시 |
| B 창 새로고침 | 첫 사진부터 재생하지 않고 서버 위치로 복귀 |
| 서버 pause 요청 | A와 B 모두 다음 상태 조회 후 정지 |
| 서버 start 요청 | A와 B 모두 기존 위치에서 재개 |
| 서버 reset 요청 | A와 B 모두 새 세션 1회차로 이동, 알림 건수 새 집계 |
| A 창에서 분석 시작 버튼 | A와 B 모두 처음부터 재생, 세션과 알림 건수 유지 |
| A 창에서 Set 변경 | 서버 위치와 B의 선택 Set에 영향 없이 선택 Set의 현재 데이터 표시 |
| A 창에서 알림의 모니터링으로 이동 | A만 과거 알림 조회 화면으로 전환 |
| 현재 자동 모니터링으로 돌아가기 | 현재 서버 위치로 다시 연결 |
| Network 탭 확인 | 상태 GET 약 1초 간격(추론 대기 재생이면 이어서 `/inference/current`), 센서는 현재 파일 변경 때 조회 |

상태 조회는 이전 요청이 끝난 뒤 1초 뒤에 다시 보내며, 5초 안에 응답이 없으면 취소합니다.
측정 전환과 제어 명령 표시는 조회 간격과 네트워크 지연의 영향을 받습니다.
조회 사이에는 서버가 알려준 재생 속도(`playback_rate`, 현재 2배속)로 센서 위치를 보간하되 다음 측정으로의 이동은 서버
응답에 따릅니다. 추론 대기 재생에서는 `playing` 단계에서만 보간하고 대기·결과 표시 중에는 위치를 고정합니다.
연결 오류가 나면 화면 시계가 멈추고 자동 재연결을 시도합니다. 백그라운드 탭에서 돌아오면 즉시 다시 조회합니다.

센서 CSV는 캐시(`src/utils/sensorCache.js`, 용량 12개)에 보관합니다.

- 선택한 Set의 현재 센서는 즉시 요청하고, 다른 Set의 현재 센서는 한 번에 하나씩 미리 읽어 부하를 제한합니다.
- 모든 Set의 현재 센서 파일과 선택한 Set의 파일은 캐시에서 제거하지 않습니다. 용량을 넘으면 그 밖의 완료된 항목부터 정리합니다.
- 선택한 Set의 센서가 캐시에 없으면 다시 불러오고, 실패하면 1초 뒤 재시도합니다.
- 센서 CSV 조회 시간 제한은 30초이며 시간 초과 시 전체 다운로드를 다시 시작합니다.
- 파형을 먼저 표시하고 절삭 구간 표시는 별도로 불러와 나중에 그립니다.
- Set을 전환해도 진행 중인 센서 요청을 취소하지 않고 공유합니다. 캐시 키는 세션·Set·센서 URL이므로 이전 세션의 데이터가 새 화면을 덮어쓰지 않습니다.

서버의 재생 세션이 바뀌면 DB와 이미지 목록을 다시 가져옵니다.
알림 상세의 이동은 해당 접속자만 과거 알림 조회 화면으로 전환합니다.

추론 상태(`/api/monitoring/inference/current`) 응답은 늦게 도착해도 더 새로운 응답이 이미 반영되지 않았다면 그대로 반영합니다.
이전 요청의 실패가 더 새로운 성공 결과를 지우지 않습니다. 추론 상태 조회는 이미지·센서 재생을 기다리게 하지 않습니다.

서버는 접속자와 독립적으로 알림 발생 이력을 기록합니다.
알림 페이지는 현재 세션 DB 이력만 조회하며 5초 간격으로 갱신합니다. reset은 과거 DB 행을 보존하면서 전체·확인·미확인 건수를 새 세션 기준으로 집계합니다. 초기화하지 않으면 브라우저를 닫아도 서버가 같은 세션에서 기록과 회차를 계속 누적합니다.

## 추론 대기 재생

서버 응답에 `gated_playback: true`가 있으면 Set마다 다음 순서로 진행하고 화면 위 문구로 단계를 표시합니다.
각 Set은 서버의 Set별 단계(`playback_phase`)를 따르므로 Set마다 측정 위치와 회차가 다를 수 있습니다.

| 문구 | 의미 |
|---|---|
| 재생 중 · AI 추론 진행 | 이미지·센서를 재생하며 AI 추론이 진행 중 (`playing`) |
| AI 추론 완료 대기 중 | 재생이 끝나 해당 측정의 추론 결과를 기다리는 중 (`waiting`) |
| 추론 결과 표시 중 · 3초 | 해당 측정의 결과를 3초 동안 표시 (`showing`) |
| AI 추론 실패 | 추론이 실패하거나 취소됨 |
| AI 추론 실패 · 모델이 입력 데이터를 처리할 수 없음 | Serving이 입력을 거부함(`error_code: INPUT_REJECTED`) |
| 추론 상태 조회 실패 | `/inference/current` 조회 오류 |
| 재생 준비 중 | 단계 정보가 없음 |

- 추론 결과는 세션, 재생 세대(`playback_generation`), 회차, Set, 위치, 측정 ID가 모두 같은 측정에만, `showing` 단계에서만 표시합니다(`src/utils/monitoringRunIdentity.js`).
- 정답 라벨을 AI 예측으로 표시하지 않습니다. 일치하는 예측이 없으면 판정 대기로 표시합니다.
- 경고·위험 토스트는 8개 Set 전체의 `showing` 결과에서 만듭니다(`src/utils/gatedAlertFeed.js`, 150/200 μm 기준).
- 추론 대기 재생이 아니면 "자동 모니터링 · 재생 중"을, 먼저 끝난 Set은 "다음 회차 대기"를 표시합니다.

## 시연 반복 재생

서버가 `cycle_number`와 `cycle_elapsed_ms`를 반환합니다. 화면은 현재 회차를 표시하고
서버가 지정한 첫 측정으로 돌아갈 때 그래프도 서버 offset부터 다시 표시합니다.
추론 대기 재생에서는 Set 항목의 `cycle_number`를 사용합니다.
센서 원본은 같은 파일을 재사용할 수 있으며 브라우저가 회차를 독립적으로 진행하지 않습니다.
알림 상세에서 회차를 확인할 수 있습니다. 토스트에서 닫은 알림도 새 회차에서는 다시 표시됩니다.

### 알림 이력 페이지 조회

알림 목록은 서버에서 Set·단계·확인 상태를 필터링한 뒤 한 페이지 10건만 조회합니다. 전체·미확인 건수는 현재 세션 전체를 별도로 집계하며, 조회 중에는 0건으로 표시하지 않습니다. 이전·다음 버튼으로 과거 기록을 확인합니다. 첫 페이지는 자동 갱신하고, 후속 페이지는 첫 조회의 ID 상한을 유지합니다. 세션 초기화 응답(409)을 받으면 첫 페이지부터 다시 조회합니다.

프런트는 `current_total`, `current_unread`, `filtered_total` 응답이 필요하므로 백엔드를 먼저 배포합니다.

### 자동 모니터링 화면

데이터 파일 선택·업로드·수동 재생 설정은 Set 1~8 화면에서 제거했습니다. 이미지·CSV 업로드는 Set test에서만 합니다. 알림의 이동 버튼은 해당 알림 사진과 연결 센서를 자동 조회해 2배속으로 재생하며 백엔드 재생을 변경하지 않습니다. 과거 알림 조회 중 나타나는 현재 자동 모니터링 복귀 버튼 또는 알림 페이지의 전체 모니터링 버튼을 누르면 서버의 현재 재생 위치로 돌아갑니다. 분석 시작 버튼은 Set test와 과거 알림 조회 화면에서는 숨깁니다.
