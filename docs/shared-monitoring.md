# 서버 기준 자동 모니터링 2단계

백엔드 1단계의 `/api/monitoring/state` 응답을 받아 현재 이미지와 센서 위치를 표시합니다.
프런트 접속 시 DB 측정과 이미지 목록을 자동 조회합니다. 일반 화면에서 공통 재생의
시작·일시정지·초기화는 서버 운영자가 제어합니다.

## 로컬 확인

1. 1단계 백엔드를 `http://127.0.0.1:8001`에서 실행합니다.
2. 이 변경의 소스 파일을 실제 프런트 개발 폴더에 적용합니다.
3. 프런트 폴더의 PowerShell에서 실행합니다.

```powershell
$env:VITE_API_BASE_URL = "http://127.0.0.1:8001"
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

다른 Vite 서버가 5173을 사용하고 있으면 그 서버를 먼저 종료합니다.
백엔드의 CORS_ORIGINS에는 `http://127.0.0.1:5173`이 있어야 합니다.
브라우저에서는 `http://127.0.0.1:5173`으로 접속합니다.
운영자 제어 토큰은 프런트 환경변수에 넣지 않습니다.

아직 일정을 준비하지 않은 백엔드는 서버 재생 대기가 표시됩니다. 한 번 준비한 뒤 reset하면 기존 일정으로 새 세션 1회차가 즉시 재생됩니다.
백엔드 운영자 요청 창에서 실행합니다.

```powershell
$headers = @{ "X-Monitoring-Control-Token" = "local-monitoring-test" }
Invoke-RestMethod -Method Post `
    -Uri "http://127.0.0.1:8001/api/monitoring/start" `
    -Headers $headers -TimeoutSec 600 | Select-Object status, session_id
```

이미 실행 중이면 같은 세션을 반환합니다.

| 테스트 | 통과 기준 |
| --- | --- |
| A 창 접속 | 버튼 조작 없이 현재 이미지, 그래프, DB 결과 표시 |
| 10초 뒤 B 창 접속 | 같은 Set의 같은 측정 위치를 표시 |
| B 창 새로고침 | 첫 사진부터 재생하지 않고 서버 위치로 복귀 |
| 서버 pause 요청 | A와 B 모두 다음 상태 조회 후 정지 |
| 서버 start 요청 | A와 B 모두 기존 위치에서 재개 |
| 서버 reset 요청 | A와 B 모두 새 세션 1회차로 이동, 알림 건수 새 집계 |
| A 창에서 Set 변경 | 서버 위치와 B의 선택 Set에 영향 없이 선택 Set의 현재 데이터 표시 |
| A 창에서 개별 수동 설정 열기 | A만 수동 확인 모드로 전환 |
| 공통 모니터링으로 돌아가기 | 현재 서버 위치로 다시 연결 |
| Network 탭 확인 | 상태 GET은 약 1초 간격, 센서는 현재 파일 변경 때 조회 |

상태 조회는 1초 간격이므로 측정 전환과 제어 명령 표시는 조회 간격과 네트워크 지연의
영향을 받습니다. 조회 사이에는 센서 위치를 보간하되 다음 측정으로의 이동은 서버
응답에 따릅니다. 연결 오류가 나면 화면 시계가 멈추고 자동 재연결을 시도합니다.
현재 선택한 Set의 센서만 다운로드하고 최근 센서 3개를 메모리에 유지합니다.

서버의 재생 세션이 바뀌면 DB와 이미지 목록을 다시 가져옵니다.
알림 상세의 이동은 해당 접속자만 수동 확인 모드로 전환합니다.
API 상태와 새로 선택한 센서의 응답이 늦게 도착해도 이전 화면의 데이터를 덮어쓰지 않도록
요청을 취소합니다.

3단계 공통 알림 변경을 함께 적용하면 서버가 접속자와 독립적으로 발생 이력을 기록합니다.
알림 페이지는 현재 세션 DB 이력만 조회하며 5초 간격으로 갱신합니다. reset은 과거 DB 행을 보존하면서 전체·확인·미확인 건수를 새 세션 기준으로 집계합니다. 초기화하지 않으면 브라우저를 닫아도 서버 worker가 같은 세션에서 기록과 회차를 계속 누적합니다.

## 코드와 검사

- `src/hooks/useSharedMonitoring.js` 공통 상태 조회, 시간 투영, 선택 센서 조회·캐시
- `src/utils/sharedMonitoring.js` 상태 검증, 시간 보간, DB 페이지 조회
- `src/hooks/useDashboard.js` 자동 조회와 기존 DB 결과·이미지·그래프 연결
- `src/components/PlaybackControls.jsx` 서버 상태와 Set별 진행 정보 표시
- `src/components/AlertsPage.jsx` 알림 이동 안내 수정
- `tests/sharedMonitoring.test.js` 늦은 접속, 일시정지, 경계, 페이지 조회 검증

```powershell
node --test tests/sharedMonitoring.test.js
npm.cmd run build
npm.cmd run lint
```

빌드가 통과하고 Node 회귀 테스트 7개가 통과했습니다. 별도의 React 실행 검사에서
자동 로드, 늦은 접속, 센서 재다운로드 방지, 일시정지, 오래된 응답 취소, 초기화를
확인했습니다. 실제 두 브라우저와 로컬 백엔드의 연결은 위 절차로 검증해야 합니다.
기존 코드의 lint 경고는 남아 있습니다.


## 시연 반복 재생

서버가 `cycle_number`와 `cycle_elapsed_ms`를 반환합니다. 화면은 현재 회차를 표시하고
서버가 지정한 첫 측정으로 돌아갈 때 그래프도 서버 offset부터 다시 표시합니다.
센서 원본은 같은 파일을 재사용할 수 있으며 브라우저가 회차를 독립적으로 진행하지 않습니다.
알림 상세에서 회차를 확인할 수 있습니다. 팝업에서 닫은 알림도 새 회차에서는 다시 표시됩니다.
